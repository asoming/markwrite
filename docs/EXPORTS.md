# PDF / DOCX 导出

菜单中的导出操作读取当前编辑缓冲区，无需先覆盖 Markdown 源文件。桌面版
通过系统保存对话框选择位置，取消不会创建文件；写入使用临时文件和原子替换，
避免写到一半破坏已有导出文件。浏览器预览版使用下载。

## 实现

- PDF 使用 pdfmake 在本地生成 A4 文档，正文是可选择文本，按内容自动分页，
  中文 Regular / Bold 字体随应用内置并按使用字形嵌入 PDF。
- DOCX 是真实 OOXML 压缩包，标题、段落、表格、链接和格式文字可以在文字
  处理软件中继续编辑。页边距、标题级别和页码写入文档结构。
- 公式转换为 MathJax 静态 SVG 路径，Mermaid 使用阅读模式已生成的 SVG。
  DOCX 同时嵌入 SVG 与 PNG 后备图，供不支持 SVG 的阅读器使用。公式与图表
  在 DOCX 中作为图形保留，而非可编辑的 Office 数学公式或流程图对象。
- PNG / JPEG 直接嵌入；浏览器支持的其他图片格式转成 PNG。公式字形、字体
  和本地附件不会在导出过程中上传到远端服务。
- 提供标准、论文、紧凑三种排版预设，控制字号、段距与页边距。

导出使用已净化且完成资源解析的阅读 DOM。丢失的图片、公式语法错误、尚未
生成的图表和合并单元格会阻止导出，并显示原因；不会生成看似成功却缺内容
的文件。

## 排版差异

- PDF 把行内公式与行内图片放到单独一行，保留原先的阅读次序；DOCX 支持
  将公式图形放在段落内。长图片等比缩放到页面可用宽高。
- PDF 的中文内置字库提供常规和粗体字形，没有独立斜体字形，因此斜体文字
  使用相同字形；DOCX 保留斜体属性，由阅读器显示。
- 任意 HTML / CSS 的网页布局、合并单元格、脚本和活动内容不属于 PDF /
  DOCX 格式映射。代码文本、缩进和换行保留，但不保证与编辑器同样的配色。
- DOCX 正文不嵌入完整的中文字体，使用目标系统的中文字体回退。不同版本的
  Word、WPS、LibreOffice 可能产生不同分页。PDF 适合固定最终版式。
- PDF 遇到内置字库不支持的字符（例如部分 Emoji）会列出字符并停止，提示
  改用 DOCX / HTML 或替换字符，不会无声输出空白方框。

## 验证

`npm test` 包含实际导出测试：中文、粗体、链接、嵌套列表、任务、代码换行、
结构化表格、公式 SVG 和图表媒体，以及对缺失资源的错误处理。PDF 测试使用
随包字体生成真实文件；DOCX 测试检查 ZIP 中的 XML 和关系，而非仅检查扩展名。

Linux 上生成的多页 PDF 已通过 Poppler 文本提取和页面渲染检查。真实浏览器
已生成包含中文、行内与块级公式、Mermaid 和图片的 PDF / DOCX；其中 DOCX
又经 LibreOffice 7.3 转换为两页 PDF，并逐页检查了内容和分页，公式、图表
与大图片无裁切。测试过程中修复了行内公式截断、Mermaid 样式和百分比宽度、
DOCX 固定行高裁切图片的问题，并增加了回归覆盖。

单元测试用 DOCX 的 SVG 后备图是最小夹具；真实浏览器测试使用实际画布生成
完整 PNG 后备图。Windows 原生导出流程，以及 Word / WPS 的不同版本仍需
对应环境验证，Linux 上的 LibreOffice 检查不替代这些结果。

若需在本地保留测试生成的文件：

```bash
MARKWRITE_EXPORT_FIXTURES=./work/export-validation npm test -- tests/export.test.ts
```
