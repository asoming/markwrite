# Markdown 桌面编辑器 PRD

版本：v0.1 · 日期：2026-09-11 · 状态：待评审

产品名称：待定，本文暂称「Markdown 编辑器」。

本文定义产品需求与验收边界，不代表功能已经实现，也不承诺全面超越 Typora。开发应先证明编辑与文件可靠性，再扩充功能。本文不构成发布、安装系统依赖或接入外部服务的授权。

## 1. 已确认的决策

| 项目 | 已确认方向 |
| --- | --- |
| 产品形态 | 对标 Typora 的 Markdown 编辑与查看桌面应用 |
| 首要平台 | Linux |
| 优先级 | 功能正确、稳定可用，其次是功能数量和视觉细节 |
| 界面目标 | 简洁，正文优先，高级功能按需出现 |
| 应用技术栈 | Tauri 2 + React + TypeScript + Rust |
| 当前工作 | 编写与评审 PRD，尚未开始应用开发 |

其余具体交互、阶段划分、性能数字均为本版建议。CodeMirror 6 是优先验证的编辑内核，能否满足即时渲染要求需要通过原型验证。

## 2. 产品目标

打造一款本地优先的 Markdown 桌面编辑器，让用户打开文件就能阅读、编写和管理文档，不依赖账号或网络完成核心工作。

以 Typora 的连续写作体验为基础目标，在文件管理、可恢复性和文档关联方面形成优势。不能以增加功能为理由破坏光标、选区、撤销、中文输入或文件内容。

### 2.1 目标用户与场景

首要用户为在 Linux 上编写技术文档、项目说明和日常笔记的人。设计同时照顾只想阅读 `.md` 文件的用户。

| 场景 | 用户需要 | 成功结果 |
| --- | --- | --- |
| 打开单篇文档 | 双击或从应用打开文件 | 内容正确显示，能快速进入编辑或阅读 |
| 长时间写作 | 持续输入、修改结构、插入内容 | 输入流畅，选区稳定，撤销可预测 |
| 管理项目文档 | 浏览目录、搜索、同时打开多篇文档 | 快速定位文件，切换不丢编辑位置 |
| 编辑复杂内容 | 操作列表、表格、代码、公式和图表 | 修改和渲染结果一致，错误可定位 |
| 与其他工具共用文件 | 使用 Git、其他编辑器或外部同步工具 | 文件仍是普通 Markdown，外部修改不被静默覆盖 |
| 从错误中恢复 | 误编辑、意外关闭、写入失败 | 能发现保存状态，恢复最近内容 |

### 2.2 产品原则

1. 数据可靠性优先于动画、装饰和功能数量。
2. 文件是用户的数据源；数据库只存可重建索引或辅助信息。
3. 默认界面只保留写作所需的信息。
4. 核心功能离线可用，不要求注册或登录。
5. Markdown 原文优先，不静默丢弃未知语法或重写整篇格式。
6. 功能是否完成，以真实用户路径和测试结果为依据。

### 2.3 首版非目标

- 多人实时协作、移动端、云端账号与自建同步服务。
- 插件市场、知识图谱大屏、复杂数据库笔记系统。
- AI 自动改写、自动执行代码或自动发布内容。
- 完整兼容所有 Markdown 方言或任意 HTML 页面。
- 一次性覆盖 Windows、macOS 和全部 Linux 发行版。

## 3. 版本范围与优先级

P0 为 v1.0 发布门槛；P1 为首版之后的增强；P2 为后续候选。P0 不允许用静态按钮、仅预览或不可保存的演示代替。

| 模块 | P0：可靠首版 | P1：形成优势 | P2：扩展 |
| --- | --- | --- | --- |
| 编辑 | 即时渲染、源码、阅读；撤销重做；查找替换 | 文档并排对照、段落移动 | 自定义编辑扩展 |
| Markdown | 标题、列表、引用、任务、表格、链接、图片、代码、公式、Mermaid | 更多方言与自定义语法 | 插件语法 |
| 文件 | 单文件、文件夹、文件树、多标签、创建与重命名 | 安全删除到回收站、批量操作 | 多工作区增强 |
| 导航 | 大纲、标题跳转、文件名搜索、全文搜索 | 双链、反向链接、标签检索 | 高级关联视图 |
| 保存恢复 | 自动保存、手动保存、崩溃恢复、外部冲突保护 | 历史浏览、差异对比、按版本恢复 | Git 集成 |
| 图片附件 | 拖入、粘贴、相对路径、本地展示 | 附件面板、引用检查、清理预览 | 可选图床 |
| 表格 | 原文编辑、正确渲染、基本增删行列 | 可视化对齐与更强粘贴能力 | 高级表格扩展 |
| 输出 | 保存 Markdown、导出 HTML | PDF、DOCX、导出模板 | 发布集成 |
| 外观 | 浅色、深色、系统主题；字号与宽度；专注模式 | 自定义主题、阅读排版预设 | 主题扩展 |
| AI | 无 | 无，独立评审是否提前 | 用户主动触发、修改预览、可撤销 |

PDF 导出不作为首版门槛，因为 Linux 打印路径需要单独验证。若用户要求首版 PDF，应显式调整范围和验收，不以未经验证的跨平台打印能力承诺交付。

## 4. 信息架构与界面

### 4.1 主窗口

```text
┌──────────────────────────────────────────────────────────────┐
│ 侧栏开关   项目笔记 / 设计说明          搜索   阅读   ···      │
├──────────────┬───────────────────────────────────────────────┤
│ 文件  大纲   │  设计说明.md   接口约定.md                     │
│              ├───────────────────────────────────────────────┤
│ 搜索文件…    │                                               │
│              │          设计说明                             │
│ ▾ 项目笔记   │                                               │
│   设计说明   │          在这里开始编写正文。                   │
│   接口约定   │                                               │
│ ▾ 日常记录   │          二、交互设计                           │
│              │                                               │
├──────────────┴───────────────────────────────────────────────┤
│ 已保存                              1,280 字   UTF-8   100%  │
└──────────────────────────────────────────────────────────────┘
```

| 区域 | 规则 |
| --- | --- |
| 顶栏 | 保留文件位置、搜索、模式入口和更多菜单；首版保留系统窗口边框 |
| 左侧栏 | 文件与大纲切换；默认宽约 240px，可调整或收起 |
| 标签栏 | 多文档时显示；单文档默认隐藏；显示未保存或冲突状态 |
| 正文 | 默认宽约 760px，支持宽屏；表格和长代码可在内容区横向滚动 |
| 右侧面板 | 默认关闭；P1 历史、反向链接等共用一个区域，避免多栏挤压正文 |
| 状态栏 | 显示保存状态、字数、编码、缩放；失败或冲突时提供明确操作 |
| 专注模式 | 隐藏辅助区域，可通过快捷键和菜单退出 |

窄窗口优先隐藏辅助面板；正文可用宽度低于约 560px 时，侧栏改为覆盖式面板。首版验收包含 1024×768、1920×1080 和 125%／150% 显示缩放。

### 4.2 视觉方向

| 设计项 | 建议 |
| --- | --- |
| 浅色正文背景 | `#FCFCFD` |
| 侧栏背景 | `#F3F4F6` |
| 正文／次要文字 | `#24272E` / `#737B89` |
| 分隔线／强调色 | `#E4E7EC` / `#4361D9` |
| 界面字体 | Linux 系统无衬线字体，中文优先匹配思源黑体或 Noto Sans CJK |
| 正文字体 | 默认清晰的无衬线字体，可调；不依赖用户安装指定字体才能正确显示 |
| 代码字体 | 优先 JetBrains Mono，回退系统等宽字体 |
| 正文排版 | 初始字号 17px、行高 1.8，可设置 |

深色主题使用独立配色，不直接反转颜色。交互文字和焦点样式需有足够对比度；状态不能仅用颜色区分。减少无功能意义的动效，支持减少动画设置。

选中文字可出现轻量格式工具条，但不能遮挡选区或干扰输入法。段落侧边操作点作为 P1 设计候选，不属于首版发布门槛。

### 4.3 主要入口

- `Ctrl+P`：快速打开文件。
- `Ctrl+K`：命令面板，集中搜索可用操作。
- `Ctrl+S`：立即保存；未命名文档进入另存为流程。
- `Ctrl+F`：文内查找，支持进入替换。
- `Ctrl+Shift+F`：文件夹全文搜索。
- `Ctrl+Z` / `Ctrl+Shift+Z`：撤销／重做。
- 模式切换、专注模式和侧栏操作均有菜单入口，不依赖记忆快捷键。

快捷键需在目标 Linux 桌面环境验证；如与系统冲突，调整默认值并在界面同步显示。

## 5. 功能需求

### F01：打开与管理文件（P0）

- 支持打开 `.md`、`.markdown` 文件及一个本地文件夹；支持中文和空格路径。
- 支持应用内打开、拖入文件及安装后的文件关联打开。
- 文件树支持创建文档、创建文件夹、重命名和刷新；同路径不重复打开标签。
- 重命名需检查重名，更新已打开文档的内部路径；P0 不自动重写其他文档中的链接，界面说明其影响。
- 文件被外部删除或移动时，保留当前编辑缓冲区，允许另存为。
- 未命名文档保存到用户指定路径，不静默写入随机目录。
- 全文搜索和目录扫描只在用户打开的文件夹内进行；不自动跟随指向文件夹外部的目录符号链接。

验收：中文路径、只读目录、文件重名、外部删除和关闭未保存标签均能得到明确结果，不丢失缓冲区内容。

### F02：三种文档模式（P0）

1. 即时渲染：作为默认编辑模式，隐藏非活动区域中适合隐藏的语法标记；光标进入时按需要显示可编辑语法。
2. 源码模式：显示完整 Markdown，适合精确修改和处理未知语法。
3. 阅读模式：禁止修改正文，支持选择复制、目录跳转和链接浏览。

三种模式共用同一文档内容，不各自维护独立副本。切换编辑模式保留撤销历史，并尽可能定位到同一段落；阅读模式返回编辑时恢复之前的编辑位置。

即时渲染的光标、跨块选区、删除行为和表格操作必须通过原型验证。对不能安全提供可视化编辑的结构，保留可访问的源码入口。

验收：连续编辑、模式切换、撤销和保存后内容一致；阅读模式不能通过键入或粘贴改变文档。

### F03：Markdown 兼容性（P0）

基线为 CommonMark，增加明确列出的 GFM 与扩展语法。编辑、阅读、HTML 导出应使用同一套语法约定和测试样例。

| 内容 | 首版行为 |
| --- | --- |
| 标题、段落、强调、删除线、引用、分隔线 | 正确编辑与渲染 |
| 有序／无序列表、嵌套列表 | 回车延续、缩进与退格行为一致 |
| 任务列表 | 勾选结果写回 Markdown，支持撤销 |
| 表格 | 支持 GFM 表格、基本增删行列；复杂内容可以源码编辑 |
| 链接与图片 | 支持常见行内和引用式语法、本地相对路径 |
| 代码块 | 支持围栏代码与语言标识、语法高亮；不执行代码 |
| 数学公式 | 支持 `$...$` 和 `$$...$$`，转义及货币符号等边界以测试样例固定 |
| Mermaid | 支持 `mermaid` 围栏渲染、源码修改；错误在块内提示 |
| YAML Front Matter | 保留原文，提供源码编辑；首版不提供结构化表单 |
| HTML／未知扩展 | 保留原文；仅渲染经净化的支持子集，其余提供源码展示 |

未修改文件不得因打开、切换模式或保存而发生格式变化。编辑局部内容时不得无故重排未编辑段落，不能用丢弃未知节点的方式完成序列化。

### F04：输入与基础编辑（P0）

- 支持中文输入法组合输入、选词、撤销、方向键移动和鼠标选区。
- 支持跨段落复制粘贴、纯文本粘贴、常见富文本粘贴转换；不能可靠转换时保留为纯文本。
- 输入法组合期间不触发会重建编辑器或打断输入的格式转换。
- 支持文内查找替换、大小写选项；全部替换可整体撤销。
- 不在正文更新时销毁重建编辑器，不通过全量重新赋值模拟每次键入。

验收：覆盖标题边界、嵌套列表、代码块、表格和中英文混排中的连续输入与选区删除。

### F05：保存、恢复与冲突（P0）

- 已有路径的文档默认在停止输入约 800ms 后触发自动保存；输入法组合未结束时延后。
- 自动保存可关闭；`Ctrl+S` 始终支持立即保存。
- 保存状态至少包含：未保存、保存中、已保存、保存失败、外部冲突。只有写入成功后才能显示「已保存」。
- 采用适合目标文件系统的安全写入策略；临时文件或替换失败不得破坏现有文件。
- 未命名草稿和未写入磁盘的修改保存在应用恢复区，恢复目标为最多丢失最近 5 秒编辑；正常退出需要完成刷新或保留恢复副本。
- 发现磁盘版本变化时：当前无修改则刷新并尽量保留位置；当前有修改则暂停自动覆盖，展示冲突状态。
- 冲突操作包括查看差异、采用磁盘版本、将当前内容另存副本，以及用户明确选择后覆盖磁盘版本。覆盖前保留被覆盖版本的恢复副本。
- 写入前校验磁盘版本，检测后续竞争变化；恢复副本用于降低并发修改造成的损失，不宣称可对任意外部程序提供完全互斥。
- 关闭有未保存修改或保存失败的文档时，提供保存、放弃、取消；放弃必须是明确选择。

崩溃恢复不等同于 P1 的完整历史系统。P0 只需恢复最近草稿和受保护的冲突副本。

验收：模拟权限失败、存储空间不足、应用进程终止、外部同时修改；不得出现失败后显示已保存或冲突后静默覆盖。

### F06：图片与附件（P0）

- 支持将图片文件拖入正文、从剪贴板粘贴图片。
- 已保存文档默认把新增图片写入文档旁的 `assets/`，使用安全的唯一文件名并插入相对路径；保留用户原始图片。
- 未命名文档先把图片放入恢复区，首次保存时迁移到目标附件目录，并在完成后更新路径。
- 图片写入成功后再提交引用；失败则保留重试机会，不制造看似成功的断链。
- 缺失图片显示占位和路径；网络图片默认不自动请求，提供主动加载入口并说明会访问远端。
- HTML 导出默认把本地图片复制到导出附件目录；附件清理与未引用文件删除留到 P1，必须先展示候选。

验收：中文文件名、同名图片、保存迁移失败、离线环境和缺失附件均可处理。

### F07：搜索与导航（P0）

- 文件名搜索与全文搜索分离；全文搜索返回文件、片段和匹配位置，可取消任务。
- 初始全文搜索为字面文本搜索，支持中文，不承诺正则和语义搜索。
- 搜索当前文件夹的 Markdown 文件，默认排除 `.git`、`node_modules` 和二进制文件；排除规则可在设置查看。
- 打开的文档优先使用当前缓冲区，避免搜索结果忽略尚未落盘的修改。
- 大纲实时提取标题，支持点击跳转；重名标题按稳定规则生成文档内目标。
- 最近文件列表支持移除失效记录，打开失败不创建空文件冒充原文件。

验收：结果可定位到对应内容，取消后不再用旧任务结果覆盖新查询。

### F08：HTML 导出（P0）

- 用户主动选择目标位置，导出当前缓冲区内容；不要求先覆盖原 Markdown。
- 生成 UTF-8 HTML，包含文档样式，支持可选目录与浅色／深色外观。
- 本地图片、公式及 Mermaid 的导出结果应能离线查看；优先把公式和图表转换为静态结果。
- 导出不得包含文档中的可执行脚本；无法支持的内容提示清单，不无声丢弃。
- 同名文件覆盖需要明确确认；导出失败不得破坏源文档。

验收：用独立浏览器离线打开导出文件，标题、表格、代码、图片、公式和图表与阅读模式在内容上保持一致。

### F09：设置与可访问性（P0）

- 设置包括主题、正文和代码字体、字号、行高、正文宽度、自动保存及基础附件规则。
- 设置本地保存，重启生效；提供恢复默认值。
- 常用操作可通过键盘完成，面板切换后焦点可返回正文；支持明确可见的键盘焦点。
- 图标按钮有可访问名称；错误提示包含操作建议，不只显示错误码。
- 无文件时提供「新建文档」「打开文件」「打开文件夹」；无搜索结果时保留查询和清除入口。

## 6. 后续增强边界

### 6.1 本地历史与差异（P1）

提供历史列表、版本差异预览和恢复；恢复本身创建新版本。保留周期、空间上限和清理规则需在实现前确定。历史不是备份服务，不承诺覆盖整个磁盘故障。

### 6.2 双链与反向链接（P1）

支持 `[[文档]]` 和标题目标，提供名称冲突选择、断链提示与反向链接。索引可重建；批量修复链接前展示影响文件和改动。

### 6.3 PDF／DOCX（P1）

先验证 Linux 上的字体、分页、图片和图表。DOCX 可评估 Pandoc，但依赖获取、版本和安装方式需要单独设计。导出不能只保证文件生成而不验证内容。

### 6.4 AI、Git 和插件（P2）

独立需求评审后启动。AI 只处理用户明确选定的内容，展示变更预览，接受后可撤销；不默认上传文档。Git 操作须有可理解的状态与冲突界面。插件需要权限和兼容性设计，不在首版预留一个未定义的开放执行入口。

## 7. 技术方案与边界

本节是约束实现的方案建议；具体模块 API 和目录结构另写技术设计。

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2 | 窗口、菜单、文件关联、本地能力桥接 |
| 应用界面 | React + TypeScript + Vite | 文件树、标签、设置、搜索和状态反馈 |
| 编辑器 | CodeMirror 6，待原型验收 | 原文状态、编辑事务、选区、撤销、即时渲染扩展 |
| Markdown | remark / rehype 等，具体组合待验证 | 语法处理、阅读渲染与导出 |
| 公式与图表 | KaTeX / Mermaid | 受限制的渲染，不执行文档脚本 |
| 本地服务 | Rust | 文件读写、目录监听、搜索、恢复和冲突保护 |
| 辅助存储 | 应用配置文件；需要时引入 SQLite | 设置、索引、历史元数据，正文不迁入私有数据库 |
| 测试 | Vitest、Rust 测试、Linux 桌面集成验证 | 单元规则、文件故障与实际输入操作 |

### 7.1 文档状态约束

- Markdown 原文是唯一可编辑内容源；阅读渲染、大纲与搜索索引为派生数据。
- 文档会话记录路径、编码、换行风格、磁盘基线、当前修改状态和恢复信息。
- P0 以 UTF-8 为写入标准，保留原文件的 UTF-8 BOM 与换行风格；非 UTF-8 文件不能静默解码覆盖，需提示转换或以受保护方式查看。
- 未改变的文件不重写；保存事件与外部文件监听事件需区分，避免循环刷新。
- 重型渲染与搜索任务支持取消或丢弃过期结果，避免阻塞输入。

### 7.2 Linux 适配

- 在确认发行版、版本、桌面环境和输入法后定义首个受支持配置；不得把「Linux」视为已经全平台验证。
- 原型重点验证 WebKitGTK、Wayland／X11、Fcitx5／IBus、剪贴板、文件选择器和显示缩放。
- 测试报告明确哪些环境已验证，未验证环境不列为正式支持。
- 安装包格式依据主发行版确定；首版交付至少一种在目标环境验证过的安装包、启动入口和文件关联。
- 如果 Tauri WebView 存在无法解决的关键输入或渲染问题，在原型阶段评估更换桌面外壳；需单独记录决策，不带着已知关键缺陷进入功能扩展。

### 7.3 本地内容与系统权限

- 文档 HTML 必须净化，脚本、事件处理属性与危险链接协议不能执行。
- 编辑渲染内容不能直接调用任意 Rust 命令；本地能力限制为明确的文件与应用操作。
- 本地附件访问限定在用户打开的文档上下文和已授权目录，防止把文档渲染入口变成任意文件读取通道。
- 外链由用户点击后交给系统浏览器；内部标题与相对文档链接在应用内处理。
- 默认不采集或上传文档内容；诊断信息不包含正文和敏感文件路径。

## 8. 非功能指标与验收方法

以下为初始验收目标，不是已有性能承诺。基准硬件暂按 4 核 CPU、16GB 内存、SSD；原型阶段记录实际 CPU、发行版、WebView 与输入法版本。若需调整目标，应在扩大开发前评审。

| 项目 | 初始目标 | 验证方法 |
| --- | --- | --- |
| 冷启动 | 10 次测量中至少 9 次在 3 秒内可输入 | 无缓存热启动替代，记录启动到可输入时间 |
| 常规文档 | 1MB、约 2 万行混合 Markdown 在 2 秒内可编辑 | 图片和图表可渐进渲染，文本优先 |
| 输入响应 | 常规文档输入到画面更新 P95 ≤ 50ms | 排除输入法候选选择时间，混合中英文持续输入 |
| 大文档 | 10MB、约 20 万行在 5 秒内进入可编辑状态 | 可提示切源码性能模式，不能假死或截断内容 |
| 全文搜索 | 1 万文件、总计约 100MB：首批结果 ≤ 1 秒、完成 ≤ 5 秒 | 本地 SSD，搜索可取消；记录冷热缓存条件 |
| 自动保存 | 常规文档从最后一次输入到成功状态通常 ≤ 2 秒 | 可控本地磁盘；失败独立提示，不伪造成功 |
| 连续使用 | 2 小时混合编辑和 100 次切换无崩溃 | 记录内存趋势、句柄和监听器泄漏线索 |
| 恢复 | 强制结束进程后找回最近草稿 | 覆盖已命名、未命名、带图片和保存失败情况 |

首版不预先承诺固定内存占用。原型报告记录空闲、常规文档和多图文档的内存，依据实测设定回归预算。

### 8.1 发布阻断问题

以下任一问题未解决，不能标记 v1.0 达到发布条件：

- 文件丢失、未知内容被静默删除、磁盘冲突被静默覆盖。
- 保存失败却显示成功，或恢复流程找不到承诺保留的草稿。
- 目标输入法环境下稳定复现吞字、重复输入、撤销破坏内容。
- 正常编辑路径持续崩溃，或文档内容能执行脚本／越权调用本地能力。
- P0 功能只有演示界面，核心路径无法完成。

## 10. 关键风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 即时渲染只做到外观，编辑行为不完整 | 看似可用但无法持续写作 | M1 用真实输入、跨块选区和撤销验证，不能只评审截图 |
| WebView 与输入法兼容性 | 中文输入无法可靠使用 | 在用户环境提前验证，必要时重新评审外壳 |
| Markdown 解析与渲染规则分叉 | 编辑、阅读和导出内容不一致 | 共享语法约定与样例集，未知内容保留 |
| 文件监听与自动保存竞争 | 覆盖外部修改或循环刷新 | 版本基线、保存前检测、冲突状态和恢复副本 |
| 图片或图表拖慢正文 | 打字卡顿或页面无响应 | 延迟渲染、缓存、过期任务取消和大文档降级 |
| 不断追加高级功能 | 核心编辑长期不稳定 | P0 验收优先，P1/P2 单独排期 |
| Linux 环境范围过大 | 无法判断兼容性是否达标 | 首版明确受支持配置，逐步扩展矩阵 |
