## 实际界面与输出检查

真实浏览器中已检查中文文字输入、任务勾选、标签切换后撤销、源码/即时/阅读切换、表格、KaTeX 公式、中文 Mermaid 图表、大纲、主题、命令面板、专注布局，以及刷新恢复草稿和设置。输入文字与真实输入法选词是不同检查，后者尚未验收。

HTML 导出已在浏览器检查内嵌资源与离线阅读路径。实际浏览器同时调用正式 PDF/DOCX 生成模块，生成包含中文、粗体/斜体、链接、代码、嵌套列表、表格、行内与块级公式、Mermaid 及图片的文件：

- PDF 可提取中文文本，内嵌字形，分页后的公式、图表与图片完整。
- DOCX 是含可编辑文字/表格的 OOXML 文件；经 LibreOffice 7.3 转为两页 PDF 后逐页检查，公式、Mermaid 和大图片没有裁切。
- 真实浏览器使用画布生成实际 PNG 后备图；单元测试中的最小后备图夹具没有被当作视觉验收结果。
- 检查中发现并修复了行内公式分裂导致的截断、Mermaid 百分比宽度与样式问题，以及 DOCX 固定行高裁切图像，并加入回归覆盖。

这些结果不代表任意 HTML/CSS 都能等价导出。PDF 行内公式另起一行；DOCX 公式/图表是图形；中文 DOCX 分页受目标字体影响。完整边界见 [导出说明](EXPORTS.md)。Windows 原生保存对话框和 Word/WPS 真机效果尚未验收。

## 性能诊断

### 大文档编辑组件

已独立运行可选的 1MiB、10MiB 混合 Markdown 诊断：挂载真实 Editor 组件，在文末连续执行 50 次输入事务，并检查全文与新增文字未被截断。该测试在 Node/jsdom 运行，测量组件挂载和事务耗时，**不含 App 状态、浏览器绘制、原生 WebView、磁盘或输入法**，因此不能替代 PRD 的可输入时间和绘制 P95。

正文超过 300,000 个 UTF-16 字符单位时暂停即时渲染，超过 1,000,000 个时关闭编辑器 Markdown 解析；仍保留全文编辑。大纲与字数在 Web Worker 计算，等待期间保留最近完成的结果，旧请求不会覆盖新文档状态。阈值使用 JavaScript 字符串长度，不是 UTF-8 字节大小。

### 工作区全文搜索

本机临时生成 **10,000 篇文档，共 100,250,000 字节** 后运行原生扫描。夹具刚写入，属于热文件缓存条件；不包含界面展示耗时。

| 项目               | 单次诊断结果                             |
| ------------------ | ---------------------------------------- |
| 首个命中           | 记录为 0ms（整数毫秒精度，不表示无耗时） |
| 首批 500 条结果    | 131ms                                    |
| 无命中全目录扫描   | 2,605ms                                  |
| 首次命中回调中取消 | 记录为 0ms，取消测试通过                 |

此结果支持当前扫描路径可用，不代表冷盘、多次统计或所有机器都满足 PRD。普通搜索最多返回 500 条；隐藏目录、node_modules、target 和符号链接按规则排除。

## 历史问题：v0.1.1 关闭按钮

用户报告点击窗口关闭按钮没有响应。定位到 Tauri 的 `onCloseRequested` 放行后会调用 `destroy()`，主窗口原先只授予 `allow-close`，缺少 `core:window:allow-destroy`；随后补充了权限。

对应两项回归直接通过 SDK 检查关闭链路和阻止关闭行为，修复前权限测试失败，修复后通过。权限回归不能单独证明所有保存状态下都可正常关闭；带未保存内容、保存失败、恢复文件刷新与取消退出仍需完整交互复核。
